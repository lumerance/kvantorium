# Кванториум-28 · универсальный инструмент педагога

Веб-приложение для педагога дополнительного образования мобильного технопарка «Кванториум-28».
Четыре инструмента в одном месте: **электронный журнал**, **набор в группы дополнительного
образования**, **счётчик часов по индивидуальному плану** и **калькулятор зарплаты**.

Работает полностью в браузере: нет сервера, нет установки, нет внешних библиотек.
Документы `.docx` и `.xlsx` разбираются прямо на странице, данные хранятся в `localStorage`
этого браузера и никуда не отправляются.

## Запуск

Любой статический сервер (ES-модули не работают по `file://`):

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

## Публикация на GitHub Pages

Сборка не нужна — репозиторий публикуется как есть:

1. **Settings → Pages → Build and deployment → Source: Deploy from a branch**
2. Выбрать ветку с кодом и папку `/ (root)`, нажать **Save**.
3. Через 1–2 минуты сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.

Ссылка работает у любого, кто её откроет, если репозиторий **публичный**
(у приватных репозиториев Pages доступны только на платных тарифах GitHub).
Сайт статический: посетитель получает пустое приложение и работает со своими файлами —
чужие данные ему не видны, потому что всё хранится в `localStorage` его собственного браузера.

## 1. Электронный журнал

**Официальный и Фактический — два независимых журнала.** Наведите курсор на кнопку «Журнал»
в шапке — выпадающий список предлагает «📋 Официальный» (сетевые документы школ) и
«📝 Фактический» (реальный состав/расписание, если отличаются от официальных). У каждого свой
импорт списка и расписания, свои группы, свои отметки — на странице «Данные» они разведены по
одноимённым вкладкам вверху. Всё остальное в этом разделе ниже одинаково устроено для обоих.

**Расписание Фактического — по дням, а не файлом.** У официального журнала расписание
загружается docx на весь заезд, а у Фактического школа обычно присылает расписание только на
завтра — поэтому на странице «Данные» вкладка «Фактический журнал» вместо файла даёт форму
«Добавить день»: дата, заезд (запоминается с прошлого раза) и построчно занятия — время, группа,
необязательная тема. Номер урока считается сам — сквозной по всему дню, по времени начала, а не
по счёту у своей группы: если после двух уроков одного класса идут два урока другого, у них всё
равно 3 и 4, а не заново 1 и 2. Группы,
которые уже встречались, — кнопками-чипами: клик сразу добавляет следующее занятие с временем
+45 минут от предыдущего. Уже внесённые дни — карточками ниже, новые сверху, с правкой и удалением.
Коды групп из этих дней сопоставляются со списком обучающихся тем же механизмом, что и у
официального расписания.

Часть детей обычно совпадает по ФИО в обоих журналах. На официальном журнале появляется кнопка
**«🔁 Перенести из Фактического»** (видна, когда в Фактическом что-то загружено): она находит
совпадения по «Фамилия Имя» (без учёта регистра и отчества), считает средний балл за каждый
заезд по Фактическому и — по одобрению в модалке со списком совпадений и чекбоксами — записывает
его как ручную правку в «Итоговую ведомость» (те же данные, что правятся там вручную). Сами
отметки официального журнала не трогаются: расписания у журналов разные, перенести оценки
занятие-в-занятие нельзя, поэтому переносится именно средний балл за заезд.

**Импорт списка обучающихся (.docx).** Документ вида «Список обучающихся по программам мобильного
технопарка» разбирается автоматически: заголовок во всю ширину таблицы — учебный предмет (класс
определяется из него же), строки «Группа N» делят детей на группы. Каждая группа получает свою
вкладку. Список можно выгрузить в CSV и загрузить обратно.

Разбор устойчив к тому, как Word реально размечает такие таблицы: колонки бывают «разорваны»
служебными столбцами и склеены `gridSpan`-ами, из-за чего ФИО в разных группах лежит в разных
ячейках — поэтому ФИО и дата рождения ищутся по содержимому строки, а не по номеру колонки.
Длинную таблицу Word разрывает на границе страницы: продолжение без заголовка вливается в тот
же предмет, а не теряется. Учитывается и опечатка «Группы 5» вместо «Группа 5».

Документ обычно содержит списки двух-трёх педагогов, поэтому сразу после импорта открывается
окно «Какие группы оставить» — чужие группы снимаются галочкой и в журнал не попадают. Позже
любую группу или целый предмет можно убрать крестиком в карточке списка, а кнопка
«Только мои по расписанию» оставляет лишь те группы, которые есть в загруженном расписании.

**Импорт расписания (.docx).** Один документ — один заезд (2 учебные недели), всего 3 заезда.
Номер заезда определяется из шапки («г. Шимановск, 1 заезд»), при расхождении приложение спросит.
Из таблиц вытаскиваются даты, дни недели, номера уроков, время, педагог и код группы («Т1 РШ7»).

Если в документе расписание нескольких педагогов, открывается окно фильтра: свой педагог
отмечается автоматически по фамилии из индивидуального плана, кнопка «Только группы выбранных
педагогов» убирает чужие коды. Тот же фильтр доступен позже кнопкой «Оставить только свои».

**Сопоставление групп.** Коды расписания связываются с группами из списка автоматически:
буква — направление (Т — труд, И — информатика, Д/У — доп. образование), цифра после буквы —
номер группы, последняя цифра хвоста — класс. Любую связь можно поправить вручную.

**Отметки.** ✓ — присутствовал, «н» — не был, оценки 2–5 с цветовой шкалой (2 — красный,
3 — оранжевый, 4 — жёлтый, 5 — ярко-зелёный). Выбирается «кисть» и проставляется кликом;
правая кнопка мыши стирает; есть режим цикла по клику и кнопка «Все присутствуют».

**Средние баллы.** В конце таблицы — средний балл за заезд (только по оценкам 2–5).
Во вкладке третьего заезда добавляется колонка «Ср. за 3 заезда» — по всем трём заездам.
Журнал выгружается в CSV.

**Темы по КТП для электронного журнала.** К группе привязывается учебная программа (docx с
таблицей КТП — тема, содержание, тип занятия, часы; из PDF таблица вставляется копированием).
В официальном журнале над таблицей отметок появляется блок «📚 Темы по КТП»: часы программы
разложены по дням заезда согласно расписанию, и для каждого дня готов **склеенный текст** —
тема, тип занятия и описание сразу за все занятия этого дня, с кнопками «скопировать».
Это закрывает главную проблему: в электронном журнале на день заведено одно поле, а занятий
в этот день может быть три подряд — теперь не нужно вручную собирать текст из трёх ячеек КТП.

Программа делится по заездам так же, как у методиста: 36 часов — это 12+12+12, 34 часа —
12+12+10 (иначе третий заезд «уехал» бы на две темы). Деление подставляется автоматически и
правится вручную, есть проверка суммы. Если строка КТП рассчитана на 2 часа, она занимает два
занятия подряд, а в склейке за день не дублируется. Кнопки «Сдвиг по КТП» двигают привязку,
если занятие переносили или отменяли.

**Итоговая ведомость.** Кнопка «Создание ведомости» открывает отдельную страницу: выбираются
группы, заполняется шапка (организация, программа, агломерация, период, педагог), а оценки
подставляются автоматически — за каждый заезд берётся округлённый средний балл из журнала,
при отсутствии оценок ставится «н/а». Итоговая — округлённое среднее по трём заездам
(«н/а», если хотя бы один заезд не аттестован). Любую ячейку можно переопределить вручную.
Готовая ведомость выгружается в `.docx` по форме технопарка или отправляется на печать.

## 2. Набор в группы дополнительного образования

Кроме сетевых договоров со школами педагог набирает собственные группы ДО (У1 — углублённый
уровень, Д2 и т.д.), по 8–12 человек. Вкладка **«Набор»** ведёт этот набор целиком, вверху
страницы — переключатель **«📋 Официальный (ДО)» / «📝 Фактический (классы)»**.

**Названия групп.** Аббревиатуры берутся прямо из кодов загруженного расписания заезда: под
формой создания стоят кнопки-подсказки со всеми кодами, коды дополнительного образования
показаны ярче сетевых предметов (Т — труд, И — информатика). Клик по коду сразу создаёт группу,
а направление подставляется из легенды расписания («Д Р — Умные технологии: от кода к движению.
Вводный модуль»). Любую группу можно завести и переименовать вручную.

**Состав.** Дети добавляются по ФИО прямо в карточке группы, Enter добавляет следующего.
Поле подсказывает фамилии из уже загруженного списка обучающихся. ФИО и примечание правятся
на месте, лишний ребёнок убирается крестиком.

**Два факта по каждому ребёнку** — галочки «Договор» (договор сдан) и «Навигатор» (заявление
отправлено). Счётчики в шапке группы и сводка вверху страницы («договоры 9 из 14»,
«Навигатор 4 из 14») пересчитываются сразу. Наполняемость подсвечивается: зелёная плашка —
8–12 человек, жёлтая — недобор или перебор, под таблицей написано, скольких не хватает.

Весь набор выгружается в CSV, а списки групп — в печать/PDF отдельным бланком
(№, ФИО, договор, Навигатор, примечание).

**Связь с журналом.** Каждую группу можно привязать к коду расписания (выпадающий список
в карточке группы, по умолчанию — код, из которого группа создана) — тогда её занятия из
загруженных заездов подтягиваются в электронный журнал так же, как у сетевых предметов. Кнопка
«📋 Открыть в журнале» сразу переключает журнал на эту группу. Там группы ДО собраны
на отдельной псевдо-вкладке «Набор (ДО)» рядом с сетевыми предметами — отметки посещаемости
и оценки ведутся так же, только «Создание ведомости» для них не показывается (ведомость — форма
для сетевых предметов).

**Классы для Фактического журнала.** Вкладка «📝 Фактический (классы)» — тот же интерфейс, но
для обычных школьных классов (7А, 7Б…), которых нет в официальных сетевых документах: только
список детей, без договора, Навигатора и норматива наполняемости — класс заводится целиком, а не
делится на подгруппы, как ДО. Хранится отдельно от официального набора (свой список классов,
своя привязка к коду), связь с журналом и печать/CSV устроены так же: код привязывается к дню
из расписания Фактического журнала (см. «Расписание Фактического» выше), а «📋 Открыть в журнале»
сразу открывает класс на вкладке «Классы» внутри Фактического журнала.

## 3. Счётчик часов

Импортируется `.xlsx` «Отчёт по индивидуальному плану работы»: лист «учебная» даёт **учебные**
часы, лист «Метод, Восп» — **методические**. Читаются все виды работ с их плановыми объёмами
и категориями (внеаудиторная, учебно-методическая, воспитательная, работа с родителями,
организационная).

Годовая норма делится **поровну**: при плане 2000 часов нужно закрыть 1000 учебных
и 1000 методических. Норму можно задать вручную или взять из импортированного плана.

Часы списываются двумя способами:

* **быстрые кнопки** для типовых действий (написание учебной программы по доп. образованию — 36 ч,
  по трудам — 34 ч, корректировка программы, подготовка к занятиям, Навигатор, родительское
  собрание и т. д.);
* **ручная запись**: вид работы, дата, часы (подставляются нормативные значения из плана),
  комментарий.

У записи есть поле «Наименование группы / мероприятия» с подсказками из плана — именно оно
становится строкой в выгрузке, поэтому строки отчёта совпадают со строками исходного плана.

Таблица «Что нужно закрыть по видам работ» показывает план / списано / остаток по каждому виду.

**Выгрузка в Excel.** Кнопка «Excel по форме плана» собирает `.xlsx` с теми же двумя листами
(«учебная» и «Метод, Восп»), той же шапкой и теми же колонками видов работ, но с фактически
списанными часами. Внизу каждого листа — три итоговые строки: «Итого по видам работ»,
«План по документу» и «Осталось закрыть». Журнал списаний отдельно выгружается в CSV.

## 4. Калькулятор зарплаты

**Формат работы.** На какой ставке педагог официально оформлен (0,5 / 1 / 1,5) и есть ли вдобавок
договор ГПХ — переключается отдельным блоком вверху вкладки. Все плитки, сравнение форматов,
детальная таблица, расчётный листок и «История зарплат» пересчитываются под выбранный формат;
поле «Сумма ГПХ» показывается только когда договор ГПХ отмечен. По умолчанию — 1 ставка + ГПХ
(как было раньше), но это теперь настройка, а не жёстко зашитое предположение.

Ежемесячно вводятся два значения: **количество рабочих дней** (подставляется из встроенного
производственного календаря на 2025–2027 годы — 2025 и 2026 официальные, 2027 предварительный)
и **количество РВ** — рабочих выходных, оплачиваемых в двойном размере.

Формулы повторяют рабочую таблицу:

```
Оклад             = базовый оклад × ставка
Стоимость дня     = (оклад + интенсив + надбавка за качество) / рабочие дни
Цена одного РВ    = стоимость дня × 2
Сумма по РВ       = количество РВ × цена РВ
Районный коэф.    = (оклад + надбавка + интенсив + сумма по РВ) × 30 %
Северная надбавка = столько же
К начислению      = оклад + сумма по РВ + интенсив + РК + СН + надбавка
На руки           = к начислению − НДФЛ
```

Показываются 0,5 / 1 / 1,5 ставки, отдельно — **текущий формат** (выбранная ставка + ГПХ, если
подключен; ГПХ добавляется после вычета НДФЛ) и разница с **1,5 ставки полностью официально**:
в месяц и за год. Пятая плитка —
**стоимость одного РВ**: не просто цена дня по двойной ставке, а полный прирост зарплаты «на
руки» с учётом того, что этот же день увеличивает районный коэффициент и северную надбавку.
Значение не зависит от того, сколько РВ уже введено в основной расчёт — это предельная (маржинальная)
стоимость ещё одного дополнительного дня.

Доплата за интенсив, надбавка за качество, оклад, сумма ГПХ и ставка НДФЛ меняются в настройках.
Календарь 2027 года предварительный (постановление о переносах выходных публикуется осенью) —
любое число месяца можно поправить вручную.

**Неполный месяц.** Если часть месяца пришлась на отпуск, больничный или трудоустройство не с
первого числа, включите переключатель «Неполный месяц» и укажите фактически отработанные дни.
Оклад, доплата за интенсив и надбавка за качество урезаются пропорционально
(факт. дни / норма дней месяца), районный коэффициент и северная надбавка считаются как обычно —
30% от их суммы. Цена одного РВ при этом не урезается: работа в выходной всегда оплачивается по
цене обычного полного дня. Формула проверена на реальном расчётном листке — «Оплата по окладу»
за 3 отработанных дня из 23 совпала до копейки.

### Вкладка «История зарплат»

Архив всех сохранённых расчётов (кнопка «💾 Сохранить расчёт» на первой вкладке): годы —
колонками, в каждой 12 месяцев с суммой «на руки». Сохранение того же года и месяца повторно
**заменяет** прежнюю запись более свежей — по месяцу хранится только одна, самая новая версия.

Клик по месяцу открывает модалку с полной раскладкой — то же самое сравнение форматов и
детализацию по 0,5/1/1,5 ставки, что и на вкладке расчёта, плюс до/после вычета НДФЛ и данные
по ГПХ. Оттуда же:
- **«💰 Премия / разовая доплата»** — сумма, которая не входит в формулу (премия к празднику,
  матпомощь и т.п.), с комментарием. Облагается тем же НДФЛ и прибавляется к начислению этого
  месяца — учитывается в сумме «на руки», сравнении форматов, расчётном листке и при
  «Заполнить из истории зарплаты» на вкладке «Отпускные». Повторное сохранение с другой суммой
  не накапливается — заменяет прежнюю.
- **«🖨 Печать / PDF (как оригинал)»** — печатная копия, воспроизводящая реальный бланк организации
  почти пиксель-в-пиксель: тот же шрифт, пунктирные разделители строк, сплошная рамка,
  двухуровневая шапка таблицы. В диалоге печати браузера выбрать «Сохранить как PDF». Строится как
  HTML/CSS (`@media print`), а не через .docx — так гораздо точнее повторяется реальный документ.
- **«⤓ Word (редактируемый)»** — тот же расчётный листок в .docx, если нужен именно редактируемый
  файл (шрифт и линии воспроизведены приближённо, не пиксель-в-пиксель). ГПХ ни в печатную копию,
  ни в .docx не входит — это отдельный договор, в официальный расчётный листок по ставке
  не включается.
- **«✎ Открыть в расчёте»** — подставляет сохранённые параметры этого месяца обратно в калькулятор
  для правки и пересчёта.
- **«🗑 Удалить»** — убирает запись из истории.

Реквизиты для шапки листка (организация, подразделение, должность, ФИО, табельный номер)
заполняются один раз в свёрнутом блоке «Реквизиты для расчётного листка» над годами.

### Вкладка «Отпускные»

Внутри страницы «Зарплата» есть вторая вкладка — расчёт отпускных по официальной методике
(ст. 139 ТК РФ, Постановление Правительства №922): средний дневной заработок = сумма зарплаты
за 12 календарных месяцев, предшествующих месяцу начала отпуска, ÷ (12 × 29,3), а для месяцев,
отработанных не полностью (отпуск, больничный, командировка с сохранением среднего, неоплачиваемый
отпуск в этом месяце), вместо 29,3 берётся 29,3⁄дней_в_месяце × (дней_в_месяце − исключённых дней).

Расчёт ведётся на суммах **«на руки», без ГПХ** — именно так, как их обычно и помнят по факту,
без данных бухгалтерии до вычета НДФЛ. Математически это корректно: НДФЛ — фиксированные 13%
что с обычной зарплаты, что с отпускных, поэтому пересчёт на «чистых» суммах линейно даёт готовую
сумму отпускных на руки, без повторного вычета налога.

Как пользоваться:
1. Указать год и месяц начала отпуска — таблица сама подставит 12 предыдущих календарных месяцев.
2. Заполнить зарплату «на руки» за каждый месяц. Кнопка «Заполнить из истории зарплаты» подставит
   суммы из сохранённых расчётов на первой вкладке («1 ставка на руки»), если они сохранены за
   нужные месяцы — сохранённые там же «неполные месяцы» переносятся в «исключённые дни» оценочно.
3. Для месяцев с отпуском/больничным указать «Искл. дней» — сколько календарных дней месяца в
   расчёт не входит; зарплату в этом поле нужно указывать только за отработанную часть месяца.
4. Указать количество дней отпуска — получить среднедневной заработок и итоговую сумму отпускных.

Расчёт можно сохранить в историю и выгрузить в CSV.

## Данные

Всё хранится в `localStorage`. На странице «Данные» есть выгрузка полной резервной копии в JSON
и загрузка её обратно — так можно перенести работу на другой компьютер или браузер.
